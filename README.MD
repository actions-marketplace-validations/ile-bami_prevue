# prevue

Prevue is a composite GitHub Action that automatically creates, manages, and tears down GitHub Codespaces as on-demand preview environments for Pull Requests. 

## Features

- **On-Demand Environments**: Spins up a Codespace when a specific label (`preview-url` by default) is added to a Pull Request.
- **Port Forwarding**: Automatically forwards a designated port (e.g., your dev server port) and sets its visibility to public.
- **PR Comments**: Posts a comment on the Pull Request with a direct link to the preview URL.
- **Auto Clean-up**: Deletes the Codespace and comments when the label is removed, saving resources.
- **Configurable Label**: The trigger label can be customised per-workflow — no need to change the action itself.

---

## Action Inputs

| Input | Description | Required | Default |
|---|---|---|---|
| `forwarded_port` | The port on the Codespace container to forward (e.g., `8000`). | **Yes** | N/A |
| `labels_json` | The JSON array representing the current labels on the PR. | **Yes** | N/A |
| `codespaces_pat` | A Personal Access Token (PAT) with `codespaces` and `pull requests` read/write access. | **Yes** | N/A |
| `pr_number` | The pull request number. | **Yes** | N/A |
| `label` | The PR label name that triggers the preview environment. | No | `preview-url` |

---

## How It Works

1. **Create Codespace**: Triggered when the configured `label` (default: `preview-url`) is present in `labels_json`. It initializes a Codespace based on the repository's `.devcontainer/devcontainer.json` configuration, forwards the specified port to public visibility, and posts the preview link to the PR.
2. **Delete Codespace**: Triggered when the configured `label` is not present in `labels_json`. It finds any active Codespace associated with the PR branch and deletes it, then posts a comment indicating deletion.

---

## How to Use

Follow these steps to enable the Prevue preview environment in your repository:

1. **Create a Personal Access Token (PAT)**  
   - The PAT must have **Read and write** permissions for **Codespaces** and **Pull requests**.  
   - If the repository belongs to an organization, the PAT should be generated by a dedicated user account (due to GitHub Actions limitations).

2. **Add the PAT to your repository or organization secrets**  
   - Store the token as `PREVUE_KEY` or whatever name you want under **Settings → Secrets → Actions** (in the repository or the organization settings).

3. **Configure the workflow**  
   - Add the following workflow file (e.g., `.github/workflows/preview.yml`) to your repository.  
   - The workflow uses the `PREVUE_KEY` (or whatever you named it in step 2) secret, so ensure it matches the secret name you created.

```yaml
name: Preview Codespace

on:
  pull_request:
    types: [labeled, unlabeled]

env:
  FORWARDED_PORT: 8000
  PREVIEW_LABEL: "preview-url" # Change this to customise the trigger label

jobs:
  manage-codespace:
    # Only run the job when the configured preview label itself is added or removed
    if: github.event.label.name == 'preview-url'
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Run Codespace Manager
        uses: b4m11/prevue@v1
        with:
          codespaces_pat: ${{ secrets.PREVUE_KEY }}
          pr_number: ${{ github.event.pull_request.number }}
          forwarded_port: ${{ env.FORWARDED_PORT }}
          labels_json: ${{ toJSON(github.event.pull_request.labels.*.name) }}
          label: ${{ env.PREVIEW_LABEL }} # Optional — defaults to 'preview-url'
```

4. **Add a `devcontainer.json` to your repository**  
   Prevue uses your repository's `.devcontainer/devcontainer.json` to configure the Codespace. At minimum, the file must declare:
   - `postStartCommand` — the command to start your application inside the container
   - `forwardPorts` — the port to expose (should match `forwarded_port` in your workflow)
   - `image` - the image that the container is going to run on. You can change this depending on the base image you want to use for your codespace.

   **Example:**
   ```json
   {
     "name": "My App",
     "image": "mcr.microsoft.com/devcontainers/base:ubuntu",
     "forwardPorts": [8000],
     "postStartCommand": "python3 server.py"
   }
   ```

   Refer to the official GitHub documentation for your language:
   - 🟢 [Node.js](https://docs.github.com/en/codespaces/setting-up-your-project-for-codespaces/adding-a-dev-container-configuration/setting-up-your-nodejs-project-for-codespaces)
   - 🐍 [Python](https://docs.github.com/en/codespaces/setting-up-your-project-for-codespaces/adding-a-dev-container-configuration/setting-up-your-python-project-for-codespaces)
   - ☕ [Java](https://docs.github.com/en/codespaces/setting-up-your-project-for-codespaces/adding-a-dev-container-configuration/setting-up-your-java-project-for-codespaces)
   - 🔷 [C# (.NET)](https://docs.github.com/en/codespaces/setting-up-your-project-for-codespaces/adding-a-dev-container-configuration/setting-up-your-dotnet-project-for-codespaces)
   - 🐘 [PHP](https://docs.github.com/en/codespaces/setting-up-your-project-for-codespaces/adding-a-dev-container-configuration/setting-up-your-php-project-for-codespaces)
   - 📦 [All templates (devcontainers/templates)](https://github.com/devcontainers/templates)

With this setup, adding the `preview-url` label to a pull request will automatically spin up a preview Codespace, and removing the label will clean it up.
